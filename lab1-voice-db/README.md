# Лабораторна робота №1. Голосовий інтерфейс для управління базою даних

Вебзастосунок, у якому базою даних працівників можна керувати голосом українською мовою: переглядати, шукати, додавати, змінювати й видаляти записи.

## Запуск

Потрібен **Node.js 22.13 або новіший** (перевірено на 24.21) і браузер **Google Chrome** або **Microsoft Edge**.

```bash
npm install
npm start
```

Відкрийте http://localhost:3000, натисніть кнопку мікрофона (або клавішу `Пробіл`) і дозвольте браузеру доступ до мікрофона.

Додаткові команди:

| Команда | Що робить |
|---|---|
| `npm test` | запускає автоматичні тести (парсер команд і операції з БД) |
| `npm run dev` | запускає сервер із перезапуском після змін у коді |

Змінні середовища (необов’язкові): `PORT` — порт сервера (за замовчуванням 3000), `DB_FILE` — шлях до файлу БД (за замовчуванням `data/employees.db`). Під час першого запуску база заповнюється сімома тестовими працівниками.

## Голосові команди

| Операція | Приклади фраз |
|---|---|
| Вибірка всіх | «Вибери всіх працівників», «Покажи всіх співробітників», «Список працівників» |
| Пошук | «Знайди працівника Андрій Шевченко», «Покажи працівника з ідентифікатором 3» |
| Фільтр за посадою | «Покажи всіх розробників», «Покажи працівників з посадою менеджер» |
| Фільтр за зарплатою | «Покажи працівників із зарплатою більше 30000», «… менше ніж 28 тисяч» |
| Додавання | «Додай працівника Іван Іванов», «Додай працівника Дар’я Петренко на посаду бухгалтер із зарплатою 30 тисяч» |
| Оновлення | «Онови посаду працівника Іван Іванов на менеджер», «Зміни зарплату працівника 2 на 50000», «Зміни прізвище працівника 1 на Петренко» (змінює лише прізвище), «Зміни ім’я працівниці 1 на Ольга», «Зміни ім’я та прізвище працівника 3 на Петро Петренко» |
| Уточнення | «Зміни прізвище працівника 1» без нового значення: система спитає «Яке нове прізвище для працівника …?» і послухає відповідь («скасуй» — відміна) |
| Видалення | «Видали працівника з ідентифікатором 5», «Видали працівника Олег Мельник», після чого треба відповісти «так» або «ні» |
| Інше | «Скільки працівників», «Допомога» |

Система розпізнає синоніми (вибери / покажи / виведи / знайди, додай / створи / внеси, онови / зміни / встанови, видали / вилучи / прибери). Числа можна казати словами («п’ять», «двадцять п’ять тисяч»). Імена розпізнаються і в непрямих відмінках: «Онови посаду працівника **Івана Іванова**» знайде «Іван Іванов».

## Обґрунтування вибору технологій

| Компонент | Вибір | Чому |
|---|---|---|
| Тип застосунку | **Веб** | Працює на будь-якій ОС і на телефоні без встановлення, а мікрофон і синтез мовлення вже є в браузері. |
| Розпізнавання мовлення | **Web Speech API** (`SpeechRecognition`, мова `uk-UA`) | Безкоштовний, підтримує українську і потоково показує проміжні результати. API-ключі не потрібні, тож їх нікуди не можна «злити». У Chrome розпізнавання виконують хмарні сервіси Google, в Edge — Azure Speech, тому точність така сама, як у платних хмарних API. Обмеження: працює тільки в Chrome та Edge і потребує інтернету. |
| Захоплення аудіо | **Web Audio API** (`getUserMedia` + `AnalyserNode`) | Показує індикатор рівня звуку. Також увімкнено шумозаглушення, ехоподавлення й автопідсилення мікрофона. |
| Голосова відповідь | **SpeechSynthesis API** | Система озвучує результат, тож керувати можна без погляду на екран. |
| Сервер | **Node.js + Express** | Сервер і клієнт написані однією мовою (JavaScript), сервер мінімальний. |
| База даних | **SQLite** (вбудований модуль `node:sqlite`) | Уся база в одному файлі, не потрібні ні окремий сервер БД, ні компіляція нативних модулів. Для цього завдання вистачає з запасом. |
| Робота з БД | **Прямий SQL** через підготовлені запити | Запитів кілька, і вони прості, тому ORM тут зайвий. Параметризовані запити захищають від SQL-ін’єкцій. |
| Обробка команд | **Регулярні вирази + простий стемінг** | Результат передбачуваний, працює миттєво й офлайн і легко пояснюється. Повноцінний NLP (spaCy або NLTK) для набору CRUD-команд надлишковий. |

## Архітектура

```
Браузер                                           Сервер (Node.js)
┌──────────────────────────────────────┐         ┌───────────────────────────────────┐
│ Мікрофон → Web Speech API (uk-UA)    │  текст  │ POST /api/command                 │
│   проміжний текст на екрані          │ ──────► │  parser.js   нормалізація, regex  │
│   до 3 альтернатив розпізнавання     │         │  executor.js валідація, логіка    │
│ Web Audio API → індикатор рівня      │ ◄────── │  db.js       SQLite, SQL-запити   │
│ Таблиця, журнал, SpeechSynthesis     │  JSON   │ GET /api/employees                │
└──────────────────────────────────────┘         └───────────────────────────────────┘
```

Як обробляється команда:

1. **Розпізнавання.** Браузер повертає текст і до трьох варіантів розпізнавання. Сервер бере перший варіант, який вдалося розібрати як команду, тож помилка розпізнавання в одному слові часто не заважає.
2. **Нормалізація** ([src/parser.js](src/parser.js)). Текст переводиться в нижній регістр, прибирається пунктуація, різні апострофи зводяться до одного, числівники замінюються цифрами («двадцять п’ять тисяч» стає «25000»).
3. **Парсинг.** Текст зіставляється з шаблонами, і на виході виходить структурована команда, наприклад `{ intent: 'update', target: { name }, field: 'position', value: 'Менеджер' }`.
4. **Виконання** ([src/executor.js](src/executor.js)). Значення перевіряються, потрібний працівник шукається за id або ім’ям, виконується SQL-запит ([src/db.js](src/db.js)) і формується відповідь для екрана та озвучення.

### Структура проєкту

```
server.js            HTTP-сервер (Express), REST API
src/parser.js        нормалізація та розбір команд
src/executor.js      виконання команд, валідація, тексти відповідей
src/db.js            SQLite: схема, тестові дані, запити
public/index.html    інтерфейс
public/app.js        розпізнавання мовлення, індикатор звуку, озвучення, таблиця
public/style.css     стилі (світла й темна теми, адаптивна верстка)
test/                автоматичні тести (node:test)
```

## Зручність і безпека

- **Підтвердження видалення.** Перед видаленням система коротко питає «Видалити …? Так чи ні?» і сама вмикає мікрофон. Момент, коли можна відповідати, позначає звуковий сигнал. Система розуміє різні варіанти відповіді («так», «звісно», «ага», «ні», «не треба», «скасуй»…) і перевіряє всі варіанти розпізнавання. Нерозбірливу відповідь вона перепитує, а після трьох пауз без відповіді скасовує видалення. Масове видалення («видали всіх») заборонене.
- **Кінець команди визначає пауза.** Chrome сам обриває фразу вже після ~1 с тиші, тому розпізнавання працює в безперервному режимі, а кінець команди система визначає сама. Команда виконується після паузи заданої довжини (налаштування «Пауза завершення»: 1,5 / 2,5 / 4 / 6 с, типово 2,5 с) або одразу після повторного натискання кнопки мікрофона. Смужка під розпізнаним текстом показує, скільки лишилося до виконання. Для відповідей «так/ні» пауза коротша (1,2 с).
- **Сигнал «можна говорити».** Щоразу, коли вмикається мікрофон, лунає короткий звук (Web Audio API). Поки система говорить, мікрофон вимкнено, щоб вона не розпізнавала власний голос. Перервати озвучення й одразу говорити можна кнопкою мікрофона або Пробілом.
- **Неоднозначні імена.** Якщо під ім’я підходять кілька працівників, система показує їхні ідентифікатори й просить уточнити.
- **Захист від SQL-ін’єкцій.** Усі запити параметризовані, а назви колонок для оновлення беруться з білого списку.
- **Валідація.** Ім’я та посада можуть містити лише літери, пробіл, дефіс і апостроф (від 2 до 80 символів). Зарплата — ціле число від 0 до 10 000 000. Довжина команди — до 300 символів, тіло запиту — до 4 КБ.
- **Захист від XSS.** Дані вставляються в сторінку тільки через `textContent`.
- **Ключі API не потрібні**, тож їх неможливо витягти з клієнтського коду. Якщо перейти на Azure чи Google Cloud, ключ слід зберігати на сервері у файлі `.env` (він уже доданий у `.gitignore`).
- **Безперервний режим.** Система слухає без натискання кнопки, а під час озвучення відповіді мікрофон вимикається, щоб вона не розпізнавала власний голос.
- **Резервне введення.** Якщо браузер не підтримує розпізнавання мовлення, команди можна вводити текстом або натискати приклади.

## Тестування

Автоматичні тести (`npm test`, 14 тестів):

- нормалізація тексту й перетворення числівників на цифри;
- усі приклади команд із завдання і їхні варіації формулювань;
- фільтри вибірки (за id, ім’ям, посадою, зарплатою);
- повний цикл «додати, оновити, видалити з підтвердженням» на базі в пам’яті;
- пошук за ім’ям у непрямому відмінку;
- некоректні команди, масове видалення, спроба SQL-ін’єкції;
- вибір правильного варіанта серед альтернатив розпізнавання.

Перевірка вручну (результати варто занести у звіт):

| Сценарій | Що перевірити |
|---|---|
| Тиха кімната, чітка вимова | точність розпізнавання всіх команд із таблиці вище |
| Фоновий шум (музика, розмова) | чи спрацьовує шумозаглушення і чи рятують альтернативи |
| Інший голос, акцент, швидкий темп | стійкість до варіацій вимови |
| Числа словами й цифрами | «видали працівника п’ять» і «видали працівника 5» |
| Chrome, Edge, Firefox, телефон | кросплатформеність (у Firefox доступне лише текстове введення) |
| Затримка | час від кінця фрази до відповіді (зазвичай менше секунди) |

## Можливі покращення

- **Офлайн-розпізнавання** через Vosk (є українська модель `vosk-model-uk`). Аудіо з `getUserMedia` (PCM, 16 кГц) передається на сервер через WebSocket, і застосунок працює без інтернету, а голос не виходить за межі комп’ютера.
- **NLP-розбір** через spaCy (модель `uk_core_news`) для довільніших формулювань.
- **Кілька таблиць** (товари, клієнти). Модульна будова парсера дозволяє додати нові сутності окремими шаблонами.
- **Розгортання** на Render, Railway або Azure App Service. Для доступу до мікрофона потрібен HTTPS.
