# Лабораторна робота №4. Віртуальне меню ресторану в AR/VR

Вебзастосунок з віртуальним 3D-меню ресторану в імерсивному просторі. Меню «плаває» перед користувачем: категорії страв, картки з цінами, 3D-модель обраної страви з інгредієнтами довкола, замовлення й налаштування. Керувати можна чотирма способами:
- **погляд** — затримка на пункті ~1 с; погляд — це центр поля зору («голова») або **справжній погляд очима через вебкамеру** (з калібруванням);
- **промінь контролера** — на комп’ютері його замінює миша;
- **жести руки** — щипок, мах;
- **голос**.

Оформлене замовлення зберігається в базі даних.

Режими:
- **Емуляція окулярів** (основний, на звичайному комп’ютері). «Голова» — камера (огляд мишею, WASD), погляд — приціл у центрі екрана, «контролер» — промінь від миші, рука — з вебкамери (MediaPipe).
- **Справжні окуляри** через WebXR. У браузері Meta Quest з’являються кнопки «Увійти у VR» та «Увійти в AR» (прохідна камера). Там працюють контролери, руки (щипок) і погляд.

## Запуск

```bash
npm install        # також завантажує моделі MediaPipe: жести (~8 МБ) і обличчя з зіницями (~4 МБ)
npm start          # http://localhost:3003
npm test           # модульні тести
npm run test:e2e   # браузерні перевірки (Chrome без вікна й без звуку)
npm run test:e2e:eyes  # браузерні перевірки відстеження очей (фото обличчя замість камери)
```

## Керування

| Спосіб | Як |
|---|---|
| Погляд | Приціл у центрі екрана — ваш погляд. Затримайте його на кнопці ~1 с; смужка на кнопці й кільце прицілу показують прогрес. |
| Очі (камера) | Кнопка «Очі (камера)» → калібрування: дивитися на 9 точок, потім на 4 контрольні (≈ 35 с). Далі приціл рухається туди, куди ви дивитеся; затримка ~1 с на кнопці — вибір. Голову тримати нерухомо; якщо приціл «з’їхав» — «Калібрувати». |
| Промінь (миша) | Наведіть мишу — від «руки» йде промінь, кнопка підсвічується. Клік — вибір. |
| Рука (вебкамера) | Кнопка «Рука (камера)». Курсор — центр долоні; щипок «OK» — вибір; мах долонею вбік — гортати сторінки. |
| Голос | Кнопка «Голос». Команди: «меню», «закрити», «піца», «маргарита», «далі», «назад», «головна», «плюс», «мінус», «додай в замовлення», «замовлення», «оформити», «так» / «ні», «налаштування». |
| Огляд і рух | Затиснути ліву кнопку миші й тягнути; стрілки або Q / E; W A S D. |
| Клавіші | M — показати / сховати меню, Esc — закрити. |
| Окуляри | Курок контролера або щипок руки — вибір; бокова кнопка контролера — показати / сховати меню. |

## Функції

- **Сторінки меню:**
  - головна — 6 категорій, замовлення, налаштування;
  - категорія — картки з мініатюрами страв, гортання сторінок;
  - страва — опис, ціна, вага, калорії, кількість, «Додати», а також 3D-модель на поворотній підставці з інгредієнтами, що «плавають» довкола;
  - замовлення;
  - підтвердження;
  - налаштування.
- **Імерсивність:**
  - меню розміщується трохи нижче рівня очей (~17°), картки огортають користувача дугою;
  - якщо відвернутися більш ніж на 35°, меню плавно переміщується перед погляд (вимикається в налаштуваннях);
  - навколо — віртуальний ресторан; в AR оточення ховається.
- **Налаштування:** відстань меню, яскравість сцени, час вибору поглядом, увімкнення вибору поглядом, слідування за поглядом.
- **Перевірка точності:** 9 цілей у просторі, система підсвічує одну, користувач обирає заданим способом. Рахуються влучання, помилки, пропуски й середній час. Таблицю можна скопіювати.
- **Показники:** кадр/с і час обробки взаємодії за кадр — у шапці сторінки.

## Відстеження очей вебкамерою

Без окулярів з айтрекером погляд оцінюється звичайною вебкамерою ноутбука:

1. **MediaPipe Face Landmarker** (локально) знаходить 478 точок обличчя, серед них — центри зіниць (точки 468 і 473), а також матрицю повороту голови.
2. **Ознаки:** положення зіниці відносно куточків ока по горизонталі та відносно середини повік по вертикалі (середнє двох очей), розкриття очей (верхня повіка піднімається, коли дивимося вгору, — це підсилює слабку вертикальну ознаку) + поворот голови (yaw, pitch). Закриті очі (висота ока < 12 % ширини) — моргання, ці кадри пропускаються.
3. **Калібрування:** 9 точок по екрану. На кожній 1 с, щоб погляд «долетів», потім 1,5 с збору (точка стискається, згори лічильник «Точка 3 з 13»). Перша чверть кадрів і кадри-викиди (далекі від медіани — кліпання, погляд убік) відкидаються. Модель — гребенева регресія з квадратичними членами окремо для X і Y. Мінімальний масштаб ознак обмежено, щоб невеликий поворот голови після калібрування не давав стрибків.
4. **Оцінка точності:** 4 контрольні точки, яких не було в калібруванні. Система показує середню й найбільшу похибку в пікселях і градусах (за відстані 60 см) та малює, куди, на її думку, ви дивилися. Похибку рахує модель, яка контрольних точок не бачила; після цього модель донавчається на всіх 13 точках. На екрані результату видно живий приціл — можна одразу перевірити, чи він встигає за очима.
5. **Згладжування:** медіана кількох кадрів (прибирає поодинокі викиди), потім фільтр One Euro (гасить тремтіння, майже не запізнюючись на швидких рухах). Плавність прицілу обирається у вікні калібрування: слабка, середня (типово) або сильна — стабільніше, але приціл трохи відстає.
6. **Вибір:** та сама затримка ~1 с. Ціллю вважається кнопка, на якій погляд був найдовше за останні 300 мс, тож короткі «вискоки» на сусідні кнопки не скидають відлік. Якщо обличчя зникло з кадру — погляд нічого не обирає.

Очікувана точність вебкамери — приблизно 1,5–4° (на екрані ноутбука 60–150 пікс.), тобто достатньо для великих кнопок меню, але не для дрібних елементів. Точність залежить від освітлення, окулярів, роздільності камери й нерухомості голови.

## Захист від випадкових виборів

- Вибір поглядом — лише після затримки ~1 с, з видимим прогресом.
- Після появи нової сторінки кнопка, на якій уже «стояв» погляд, не спрацьовує, доки погляд з неї не зійде. Вибір відбувається лише свідомим наведенням («проблема Мідаса»).
- Меню висить нижче рівня очей, тож погляд «прямо» не потрапляє на кнопки.
- Оформлення замовлення — тільки через сторінку підтвердження («Так» / «Ні»).
- У режимі перевірки точності зараховуються лише вибори заданим способом.

## Обґрунтування вибору технологій

| Компонент | Вибір | Чому |
|---|---|---|
| Платформа | **WebXR + three.js** | Безкоштовний відкритий стандарт. Той самий застосунок відкривається в браузері окулярів (Meta Quest, Pico, HoloLens 2 в Edge) і на комп’ютері для розробки та демонстрації. Не потрібні Unity/Unreal, збирання APK і магазин застосунків. |
| 3D-інтерфейс | Власні панелі й кнопки (canvas → текстура) | Будь-який шрифт і українська мова; стани наведення й прогресу погляду. three.js роздається локально. |
| Жести на комп’ютері | **MediaPipe** (з лаб. 2) | Локально, безкоштовно, без хмари |
| Голос | **Web Speech API** (з лаб. 1) | Безкоштовно, українська мова |
| Сервер, БД | Node.js + Express, SQLite | Меню зберігається в базі; суму замовлення рахує сервер за цінами з бази |

**Альтернативи:**
- **Unity + Oculus Integration / Unreal + VisionOS** потребують важкого середовища, збирання під кожну гарнітуру й самої гарнітури для будь-якої перевірки.
- **Microsoft MRTK** зав’язаний на HoloLens.

WebXR дає ту саму взаємодію (контролери, руки, погляд) у браузері.

## Архітектура

```
public/js/menu-model.js     стан меню: сторінки, навігація, кількість, замовлення, підтвердження, налаштування
public/js/menu-view.js      3D-сторінки меню, модель страви з інгредієнтами, слідування за поглядом
public/js/ui3d.js           3D-панелі й кнопки (текст на canvas), підписи
public/js/dishes3d.js       процедурні 3D-моделі страв (піца, бургер, салат, суп, десерт, напій)
public/js/environment.js    віртуальний ресторан, освітлення
public/js/interaction.js    вказівники (погляд, миша, рука, контролери), наведення, затримка, час обробки
public/js/dwell.js          логіка вибору поглядом із затримкою
public/js/eye-features.js   ознаки погляду з точок обличчя (зіниці, повіки, поворот голови)
public/js/gaze-calibration.js калібрувальна регресія, похибка, фільтри (медіана, One Euro)
public/js/eye-tracker.js    вебкамера + MediaPipe Face Landmarker → точка погляду на екрані
public/js/eye-calibration.js екран калібрування (9 + 4 точки, результат)
public/js/desktop.js        емуляція окулярів: голова, промінь від миші, приціл погляду
public/js/xr.js             WebXR: VR / AR сесії, контролери й руки
public/js/hand-gestures.js  жести руки з вебкамери (курсор, щипок, мах)
public/js/voice-commands.js розбір голосових команд
public/js/accuracy.js       режим перевірки точності
src/                        REST API (меню, замовлення), SQLite, валідація
```

REST API: `GET /api/menu`, `GET /api/orders`, `POST /api/orders` (клієнт надсилає лише id страв і кількість, суму рахує сервер).

## Тестування

- `npm test` — 23 модульні тести:
  - навігація меню, сторінки, замовлення, обмеження кількості, оформлення лише з підтвердженням;
  - налаштування;
  - затримка погляду;
  - 23 голосові команди;
  - жести руки на синтетичних кадрах (курсор, щипок, мах, кулак не є щипком);
  - відмінки;
  - очі: ознаки на синтетичному обличчі, моргання, калібрування (похибка на контрольних точках), стійкість до повороту голови, фільтри, відсіювання викидів, вибір цілі за вікном;
  - REST API: серверний перерахунок суми, валідація.
- `npm run test:e2e` — 17 браузерних перевірок:
  - справжні кліки миші;
  - вибір поглядом через ~1 с, без випадкового вибору після зміни сторінки, вимкнений погляд;
  - щипок і мах рукою;
  - повний сценарій замовлення голосом;
  - підтвердження «так» / «ні», збереження в базі;
  - налаштування;
  - слідування за поглядом;
  - режим точності;
  - **час обробки взаємодії < 20 мс** (середній ~0,1 мс).
- `npm run test:e2e:eyes` — 11 перевірок очей:
  - справжній Face Landmarker на фото обличчя (фальшива камера Chrome) знаходить обличчя й зіниці;
  - скасування калібрування;
  - повне калібрування (9 + 4 точки) з імітованими очима, показ похибки;
  - вибір очима через ~1 с, стійкість до тремтіння, нічого не обирається без обличчя;
  - сервер приймає спосіб «eyes»; вимкнення очей.

> ⚠️ Справжні очі автоматично перевірити неможливо: тести підтверджують розпізнавання зіниць на фото та логіку калібрування й вибору. Точність на живих очах видно на екрані результату калібрування й у «Перевірці точності» (спосіб «Очі через вебкамеру»).

## Справжні окуляри

1. Окуляри (наприклад, Meta Quest) і комп’ютер — в одній Wi-Fi-мережі.
2. WebXR вимагає HTTPS або `localhost`. Найпростіше підключити Quest кабелем з увімкненим режимом розробника й виконати `adb reverse tcp:3003 tcp:3003`, а потім у браузері окулярів відкрити `http://localhost:3003`.
3. Натиснути «Увійти у VR» (або «Увійти в AR» для прохідної камери).

На комп’ютері без окулярів можна також встановити розширення Chrome **Immersive Web Emulator** (Meta). Воно імітує Quest, і кнопка «Увійти у VR» з’явиться у звичайному Chrome.

> ⚠️ Режим WebXR написано за специфікацією (three.js WebXRManager, контролери, hand-tracking), але **на реальних окулярах і в емуляторі Meta не перевірявся**. Усі функції перевірено в режимі емуляції.
